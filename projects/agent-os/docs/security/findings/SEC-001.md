# SEC-001 — Servidor escuta em todas as interfaces, sem autenticação

Severidade: high (qualquer máquina da rede local lê transcrições com prompts, comandos e ficheiros)
Dono: backend-dev
Localização: projects/agent-os/package.json (scripts `dev` e `start`)
Estado: Verified

## Descrição
`next dev -p 4100` escuta em 0.0.0.0 e [::]. A API não tem autenticação. Quem estiver na mesma rede (Wi-Fi de casa, escritório, café) lê tudo.

## Passos para reproduzir
`netstat -ano | grep :4100` -> `0.0.0.0:4100 LISTENING`. `curl http://<IP da LAN>:4100/api/projects` -> 200.

## Impacto
Divulgação de prompts, nomes de ficheiros, comandos, memórias e caminhos locais a terceiros na rede.

## Correção recomendada
Usar `-H 127.0.0.1` em `dev` e `start` (`next dev -p 4100 -H 127.0.0.1`). Reiniciar o servidor depois (é do tech-lead). Ver também SEC-006.

## Evidência
`TCP 0.0.0.0:4100 LISTENING`; pedido pelo IP da LAN da máquina: HTTP 200.

## Fix
package.json: `dev` = `next dev -H 127.0.0.1 -p 4100`, `start` = `next start -H 127.0.0.1 -p 4100`. Verificado com um dev server de teste em 127.0.0.1:4130 (netstat: `127.0.0.1:4130 LISTENING`, não 0.0.0.0). O servidor de dev em uso (4100) só passa a escutar em 127.0.0.1 quando o tech-lead o reiniciar.

## Reteste (2026-11-17)
netstat: `127.0.0.1:4100 LISTENING` (já não há 0.0.0.0). Pedido pelo IP da LAN: sem ligação (000). `localhost` e `127.0.0.1`: 200. Verified.
