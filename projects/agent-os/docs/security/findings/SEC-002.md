# SEC-002 — Host/Origin não validados (DNS rebinding)

Severidade: medium (um site malicioso no browser pode ler a API após rebinding; exige condições extra)
Dono: backend-dev
Localização: projects/agent-os/app/api/** (sem middleware); next.config.ts
Estado: Verified

## Descrição
O servidor responde igual a qualquer `Host`. Não há CORS aberto (bom: sem Access-Control-Allow-Origin), mas um site que faça rebinding do seu domínio para 127.0.0.1 torna-se same-origin com a API e lê tudo.

## Passos para reproduzir
`curl -H 'Host: evil.example:4100' http://localhost:4100/api/projects` -> 200.

## Impacto
Leitura remota das transcrições através do browser do utilizador.

## Correção recomendada
Middleware (`middleware.ts`) ou verificação nos handlers: aceitar só `Host` em {localhost, 127.0.0.1, [::1]} com a porta configurada e, se existir `Origin`, só o mesmo. Responder 403 caso contrário.

## Evidência
`evilhost 200`; resposta a `Origin: http://evil.example` sem cabeçalhos CORS.

## Fix
Novo middleware.ts na raiz da app: aceita só Host localhost/127.0.0.1/[::1] com porta 4100/4120/4121/4130 (403 FORBIDDEN_HOST caso contrário) e, em /api/*, rejeita Origin estrangeiro com 403. Evidência (dev em 4130): Host localhost -> 200; `Host: evil.example:4130` -> 403; `Origin: http://evil.example` -> 403. e2e ui+api: 29 passed.

## Reteste (2026-11-17)
`Host: evil.example:4100` -> 403; `Origin: http://evil.example` -> 403; `localhost` e `127.0.0.1` -> 200; UI `/` -> 200. Verified.
